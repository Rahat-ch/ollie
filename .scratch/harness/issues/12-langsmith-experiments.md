# 12: The eval's runs are LangSmith experiments

**Read first:** `CONTEXT.md` (capitalised terms are defined there); `.scratch/harness/spec.md`, Implementation Decisions › Phase 2 › LangSmith, eval only; `.scratch/harness/decisions.md` #21, 27; ADR 0002 (last consequence); research §2 and §3; `docs/research/langchain-harness.md` for background. Follow `AGENTS.md`. Deliver as one PR into `main`, merged before the next ticket starts. Never mention the former sponsor or the contest in anything you write.

**What to build:** Tracing turns on only when `pnpm eval` sets it. It is never set in production, and no route sends anything to LangSmith, as ADR 0002 records.

Each Eval Run becomes a LangSmith experiment over a dataset of Simulated Learner Sessions. The existing scorers are wrapped as custom evaluators: Evidence Integrity, Claim Agreement, Plan sources, convergence, and Story and Summary validity.

A replay target turns stored reports into experiments at no model cost. The Phase 1 Opus and Sonnet Arms become a comparative experiment.

The committed JSON reports stay the record. LangSmith is the view, on the free Developer plan.

## Comments

**2026-09-28, implementation.** Test first, against an in-memory LangSmith, since no key was available: `src/evals/langsmith/fake-client.ts` is a real `langsmith` `Client` whose dataset, experiment, run and feedback calls are answered in memory and whose HTTP client throws, so anything it does not answer fails the test instead of reaching the network. Every test asserts it received no request. `langsmith` 0.10.5 (MIT, already in the tree through `@langchain/core`) is now pinned as a devDependency of its own, and every call was checked against its installed `.d.ts` and source, not the research note. What the source showed: `evaluate` always traces its target, whatever `LANGSMITH_TRACING` says; `disableEvaluatorTracing` exists and keeps evaluators from costing traces; an evaluator that throws is logged and swallowed, so the tests count every piece of feedback; `evaluateComparative` is deprecated in favour of `evaluate` over experiments, which is used here and takes more than two of them.

- **The experiment** (`experiment.ts`, pure; `publish.ts` talks to LangSmith). The dataset is `ollie-simulated-learners-v1`, one Example per Simulated Learner, created on first use. An Example whose Learner has since changed is refused rather than overwritten. Each Learner's run returns that Learner's lines of the report and never calls a model. Five per-Learner evaluators (evidence, plan sources, naming, convergence, Summary) and one run-level evaluator (splits, Stories, Summaries, the Judge's gate, cost) hand over the report's own numbers. A withheld Judge score is the value `withheld`, never a number. A live run and a replay are the same code: `pnpm eval` makes its experiment from the report file it has just written.
- **The replay.** `publish.test.ts` replays the three live Opus 5 reports of 2026-09-18 into the fake and checks every Learner's and every run's feedback against the report files, including crossing ten named after Session 6 in two runs and never in the third, and the Judge withheld on a fake report. `pnpm eval:langsmith replay --dry-run` did the same from the command line: one dataset of 6 Examples, three experiments of 6 runs and 110 pieces of feedback each, 18 traces, 0 network requests. Sending them for real is the owner's step below.
- **The comparison.** `compareArms` scores each run per Learner against every run of the other Arm (the share it beats, a tie counting half). Its keys are fewer false positives, higher Evidence Integrity, higher claim agreement, earlier detection, and more Skills Mastered. It is tested on a second Arm built from the Opus reports. `pnpm eval:langsmith compare` refuses to run without `--b`, because ticket 07's Sonnet 5.5 reports do not exist yet. No live model eval was run.
- **Tracing.** `tracing-config.ts` decides without importing `langsmith`: tracing is on only when `LANGSMITH_TRACING=true` and `LANGSMITH_API_KEY` are both set. Otherwise `src/cli/eval.ts` never loads it. `runEvals` takes an optional `span`, and without one the run is unchanged. With tracing on, each Learner's Coach run, the Stories and the Summaries are each one trace. `Generation` and the Judge are wrapped with `traceable`, so the fake and the Anthropic adapter trace the same way and the route's adapter is untouched. The recorder writes each call's model and tokens onto the traced call. A model call outside a span is not traced, so the trace count cannot creep up. Tests: a traced fake run scores exactly what an untraced one does; it is 8 traces with every recorded call nested under one. A fake `pnpm eval` on this branch and one on `main`, both without the variables, wrote reports identical apart from `generatedAt`. With the variables set and `LANGSMITH_ENDPOINT` at a closed local port, the run wrote its report, then said the experiment was not made and exited 1, with nothing leaving the machine.
- **No route.** `no-route-tracing.test.ts` walks every import the app can make, from every file under `src/app` and the proxy, dynamic `import()` included. It fails if one reaches `langsmith`, `src/evals/langsmith` or `src/cli`, or names `traceable`, `wrapAnthropic` or a `LANGSMITH_` variable. It checks that it reached the lazily loaded Coach graph and Anthropic adapter, so it cannot pass by looking at nothing, and that the same walk from the eval commands does find `langsmith`. `scripts/bundle-check.mjs` now also searches the server and browser bundles for LangSmith's experiment runner, its Anthropic wrapper and our dataset name, each first found in its source. Both were checked the other way. With `publish.ts` imported lazily into `/api/health` for one build, `pnpm bundle:check` named the server chunk. With `tracing.ts` imported the same way, three of the test's cases failed. Writing the test also turned up that a `\bLANGSMITH_\b` pattern can never match `LANGSMITH_TRACING`, so the word check now reads the code without its comments and must find the words in the eval's own tracing modules first.

Verified with `pnpm typecheck`, `pnpm lint`, `pnpm test` (835), `pnpm build`, `pnpm bundle:check`, `pnpm licenses:check`, and `pnpm exec tsx src/cli/eval.ts --fake` (its regenerated report and charts not committed). No model call, no key.

Decided here, not in the spec. Tracing wraps `Generation` with `traceable` rather than the SDK client with `wrapAnthropic`, so the seam stays at `Generation` (ADR 0004) and nothing in `src/generation` changed. The evaluators are untraced: a run costs 14 traces rather than about 45, but their feedback cannot be corrected from LangSmith's UI, which is right while the report is the record. One experiment per report, not one per Arm with `numRepetitions`, because a target is not told which repetition it is. `pnpm eval:langsmith` needs only the key, not `LANGSMITH_TRACING`, since sending is its whole purpose. The eval now reads `.env.local` into the environment in fake mode too, so the LangSmith variables can live there. langsmith 0.10.5 prints "Can not call 'on_end'" once per untraced evaluator call; that one line is dropped while an experiment is made. A LangSmith annotation-queue import was not built: the labelling page serves both labellers, and a queue would first need the items pushed to it as runs. The README gives the shape an export must write. One risk stays with configuration: `@langchain/core` would trace the Coach route's LangGraph graph if `LANGSMITH_TRACING` were set in the container. No code of ours can turn it on, but the variable must stay unset in Coolify.

## Comments

**2026-09-28, implementation.** `.github/workflows/ci.yml` runs on every push and pull request with read-only permissions. It uses `actions/checkout@v4`, `pnpm/action-setup@v4` (the pnpm version comes from `packageManager`) and `actions/setup-node@v4` on Node 24 with the pnpm store cached. It then runs `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm eval --fake` and `pnpm build`, and a newer run on the same ref cancels the older one. The workflow references no secret, so the fake eval runs in CI with no key and no network. On PR #54 the whole job took 48 seconds: 628 tests in 69 files, the fake eval ran 6 Simulated Learners for 20 Sessions in 37 ms, and the build compiled. The report and charts the eval writes stay in the runner and are not committed.

`.github/workflows/live-smoke.yml` is `workflow_dispatch` only, with an optional `learner` input (default `crossing-ten-weakness`), and has no schedule. The job reads `secrets.ANTHROPIC_API_KEY` into its environment. When the secret is empty, the first step posts a notice saying the run was skipped and every other step is skipped, so the run ends green without installing anything or calling a model. With the secret, it runs `pnpm coach --real --learner <id> --sessions 2 --assert`. That is one Simulated Learner for three Sessions: the Diagnostic Session and two Coach-planned ones, so three Coach calls. `pnpm coach --sessions N` counts the Coach-planned Sessions after the Diagnostic Session. The smoke runs `pnpm coach` rather than `pnpm eval` because `pnpm eval` always runs all six Learners plus the Story and Summary evals, far more spend than a smoke check needs. The only code change was the smallest option that makes `pnpm coach` a check: `--assert`. It gathers the Session traces, scores them with the existing `scoreHypotheses`, prints "Evidence Integrity 1.00 over N citations; Plans: a Coach, b retry, c Baseline", and exits 1 on any failure. The two conditions are `smokeFailures` in `src/evals/smoke.ts`: Evidence Integrity below 1.00, with the count of unknown citations, and any Plan from the Baseline fallback. They are phrased as sentences so the log says what failed. With no citations at all, Evidence Integrity is 1 by the existing `integrityRate` rule. That is why the citation count is printed next to it. The smoke runs on whatever `COACH_MODEL` the adapter is set to, so it follows ticket 06's model change without edits.

Tests: `src/evals/smoke.test.ts` checks that a clean run passes, that one unknown citation fails ("Evidence Integrity 0.92 is below 1.00: 1 of 12 citations name a Problem not in the Log"), that one Baseline Plan fails, and that both failing are both named. It also runs `runLearner` end to end for one Learner and three Sessions on the fake: that run passes, and a Coach returning malformed output fails with "3 of 3 Plans came from the Baseline fallback". On the fake, `pnpm coach --sessions 2 --assert` printed "Evidence Integrity 1.00 over 5 citations; Plans: 3 Coach, 0 retry, 0 Baseline" and passed.

Red check: a throwaway branch `ci-red-check` added a test that asserts `1 === 2`, and its CI run failed on `pnpm test` (run 36500240998). The branch was deleted afterwards and never touched `main` or PR #54. The README shows the CI badge under the title; that badge is the only README change.

Not verified: starting the live smoke by hand. GitHub offers `workflow_dispatch` only for a workflow that is on the default branch, so it can be started only after merge. The repo has no Actions secrets today, so the first run will show the skip at no cost. Asserting the two conditions against the real models waits until the secret is added. That box stays unticked until then.

Found on `main`, not fixed here: `src/play/speech-pool.test.ts` › "asks again once the back-off is over, so a key that arrives later is not shut out for the life of the page" is flaky. It failed 2 times in about 9 local runs, and also in the red-check CI run next to the deliberate failure. `requestSpeech` records a refusal with `refused.set(key, Date.now())` when the fetch resolves (`src/play/speech-pool.ts:67`), not at the `now` it was called with. When the fetch resolves even 1 ms after `at`, the retry at `at + SPEECH_RETRY_MS` still falls inside the back-off and returns null. The fix is to record `now`. Until it lands, this CI can turn red at random on that test.

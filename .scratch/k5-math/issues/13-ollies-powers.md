# 13: Ollie's Powers

**What to build:** When the Learner Masters counting on, make-a-ten, unknown addend, or Unit 3, the Session's headline celebration shows Ollie learning a Power: Count-On Flight, Make-Ten Magic, Missing Number Detective, Story Solver. From then on, every matching Problem shows Ollie using it: wing beats along the number line, filling and splitting on the ten-frame, a magnifying-glass search for the missing part, richer Story variants. Powers appear on the Path, in the Parent Area, and by name in the Parent Summary. Powers are never lost and never bought.

**Blocked by:** 08 Play a Session, 10 Unit 3 Stories

**Status:** resolved

- [x] Mastery of the named Skill or Unit awards its Power exactly once and it persists
- [x] Each Power has its own animation on matching Problems, built to the character sheet poses
- [x] The Power celebration replaces the ordinary Session celebration on the Session it is earned
- [x] Story Solver switches Unit 3 to the richer Story variant set
- [ ] Path, Parent Area, and Parent Summary all show Powers by name; Badges do not exist anywhere — the Path and the Parent Area do and Badges are nowhere; the Parent Summary's list is wired after ticket 12 merges

## Comments

**2026-09-13, implementation.** The Powers are behind the Loop seam, as the spec's "Two seams" note puts them. `src/loop/powers.ts` is the catalogue and the whole of the rule: four `Power` rows in the order the progression teaches them (id, name, what must be Mastered, the Skills Ollie uses it on, and what it does in the Learner's words) — Count-On Flight from counting on, Make-Ten Magic from make-a-ten, Missing Number Detective from unknown addend, Story Solver from Unit 3, and a fifth is a spec change. `powersFor(profile)` reads the Powers a Profile's Mastery has taught (a Unit's Power waits for every Skill in that Unit), `powersEarned(before, after)` is what a Session taught, `withPowers(held, earned)` is the list afterwards, and `powerUsedOn(held, problem)` is the Power Ollie uses on a Problem. `SessionResult` gained `powersEarned` and `finishSession` fills it from the Profile before the Session and the one after, so a Power is a pure function of Mastery: earned on exactly the Session that Masters its Skill or Unit, never bought, never deducted, and never re-awarded (Mastery is latched in the Loop, and the Profile's list is a union besides). The Loop tests drive it from outside with the Simulated Learners' own answer policy: the strong Learner playing twenty counting-on Sessions teaches Ollie Count-On Flight exactly once, the weak Learner teaches it no more than once and only if the Skill is Mastered, a Session of Reveals on an already Mastered Skill earns nothing, and Story Solver arrives on the Session that Masters the second Unit 3 Skill and not the first.

The Profile keeps them: `Profile.powers`, `PROFILE_VERSION` 5, and a version-gated migration like tickets 10 and 14 — a Profile stored at version 1 to 4 is carried forward with the Powers its own Mastery has already taught (`powersFor(progress)`), so a Learner who Mastered counting on before Ollie could learn from it finds Count-On Flight waiting, and a `powers` field that is not four ids this version knows starts the Profile fresh. `beginPlay` reads the Powers onto the Play state, `celebrate` adds what the Session earned, and the Session screen writes them with the progress and the rewards when it celebrates, so celebrating the same Session twice adds nothing.

On screen: `visualFor(problem, stage, powers)` now carries the `power` the visual is drawn with (the models are otherwise byte-for-byte what they were: a Power changes how a visual is drawn, never what it says), and the Session screen puts the Power's pose on Ollie the moment a matching Problem is asked, keeping the phase's own pose where Ollie is reacting (encourage after a miss, celebrate on a right answer) and the beak on its own class, so a Power pose still speaks (ticket 11 untouched). Each Power's rig animation is in `src/ollie/ollie.css` to the character sheet's hinges: both wings beat and Ollie rises for Count-On Flight, the wing carrying the ten-frame chip lifts and the plum sparkles pulse for Make-Ten Magic, the magnifying glass searches for Missing Number Detective, the book opens for Story Solver. The visuals' own moves are in `globals.css`: sky wing beats over each hop on the number line (`src/ui/NumberLine.tsx`), a magnifying glass built from the same shapes as the pose's prop sweeping from the number known up to the whole, and flat plum rings turning out of the counters that fill the ten and the ones left over (`.ten-frame-magic`). Everything is bounded — three beats, two searches, one page turn; nothing loops — and every one of them is in the `prefers-reduced-motion` block. `src/ui/PowerMark.tsx` is each Power's mark on a plum disc (wing, ten-frame chip, glass, book), used on the Path stop, in the Parent Area, and on the celebration card.

The celebration: when a Session earns a Power the headline is the Power ("You taught me Count-On Flight!", `powerLine` in `src/play/lines.ts`, added to `ollieLines()` so `pnpm voice:lines` renders all four — Ollie's catalogue is now 124 lines and 3,191 characters), Ollie takes the Power's pose, and a plum card names it with what Ollie will do. Ticket 14's Coins and Streak cards are still there and the ten Coins are still paid; the Mastered card is still there too. Two Powers in one Session is possible (make-a-ten and unknown addend can both be Mastered at once): the first is the headline and both get a card. Story Solver switches Unit 3 to the rich Story set: `StoryInput.rich` threads through the prompt (one more line of brief: say where it happens and what the things are doing), `poolKey` (a `rich/` prefix, so the plain keys are untouched), `templateStory` (a second hand-written sentence per structure in `src/story/shapes.ts`, using a new `where` phrase per Theme built from words the Theme already allows), the `/api/story` route, `pnpm pool --rich`, and `useStories`, which asks for the rich set when the Learner has taught Story Solver. The validator is unchanged, so a rich Story is still two sentences under 25 words with exactly the engine's numbers, and a test checks the rich template is valid for every Theme and structure — the template path is what this machine shows, the bundled Pool still being empty for want of a key.

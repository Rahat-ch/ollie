# 08: Play a Session in the browser

**What to build:** A Learner opens the app on a tablet, taps Play, and plays a full Session: Ollie (an SVG in the design's style with idle, talking, celebrate, encourage) presents each Problem, the ten-frame or number line shows the visual, the Learner taps a number on a 0 to 20 pad, a first miss shows the Hint with the visual animated, a second miss shows the Reveal, and the Session ends with a celebration. A Repeat button is on every Problem. The Profile and its progress persist locally. The home screen shows Ollie, the Avatar placeholder, the Path with three Units, and one big Play button. Built to the design canvas. One browser smoke test runs the whole flow through the fake Generation.

**Blocked by:** 02 Design direction, 04 Plan Space and Baseline

**Status:** resolved

## Comments

**2026-09-12, implementation.** Two routes, both thin client components over pure modules. `/` (`src/app/Home.tsx`) shows Ollie idle with a greeting bubble, the Avatar placeholder, the Path with three Units (`pathStops` in `src/play/path.ts`: done, current, locked; Unit 3 stays locked until ticket 10 gives it Skills), and one Play link. `/play` (`src/app/play/SessionScreen.tsx`) drives a Session through the Play reducer in `src/play/play.ts`: `beginPlay` resumes the Session in progress or starts the next one from `baselinePlan` (the Diagnostic Session first), and every tap goes through the Loop's `answerProblem`, so the Assistance State comes from the engine: phases are asking, hint (after the first miss, the pad shows the tried key pressed and disabled), correct (Ollie celebrates for 1.4 s and moves on by itself), reveal (the answer filled in, a Next button), and celebration (`finishSession`, then Done goes home). Ollie is an inline SVG (`src/ollie/Ollie.tsx`) from a module generated from `public/ollie/` by `pnpm ollie:poses`, with CSS breathing, blinks, a celebrate bounce, an encourage wave, and a beak chatter while "talking", which for now lasts as long as the line takes to read (ticket 11 ties it to audio). The Repeat button replays the line on screen the same way. The ten-frame and number line render pure models from `src/play/visuals.ts` per Skill, structure, and stage: partners show the given counters with the empties counted on the Hint (missing partner) or the taken counters leaving and the rest counted (take from ten); teens show a full frame and the extras; make-a-ten puts the larger addend in the frame with the other waiting and moves just enough in on the Hint; counting on starts at the bigger number with hops drawn one at a time and the landing shown only at the Reveal; unknown addend shows both numbers and hops between them. The Profile (`src/profile/`) is the Loop's `ProfileState` plus the Session in progress and a random seed, in localStorage under `ollie.profile`, read through `useSyncExternalStore` so the server renders nothing personal; every step is written, so a reload resumes the same Problem, and a Session that ended without its celebration is finished on the next visit. Layout follows the canvas at 1024×768 (32 px gutter, 960 content, 64 px keys, Ollie bottom-left) and centres at laptop width; the Learner flow has no text input anywhere.

One Loop change: Hints are now per structure (`Skill.hints`, `hintFor(problem)`), because the Skill a Hint "count the empty spaces" was wrong for `10 − 3 = ?`, where the empty spaces are the number taken away; take-from-ten now says to count the counters that are left, and the counting-on and unknown-addend second structures got their own wording. The Generation seam is not on the browser path yet: Stories, speech, the Coach, and the Summary arrive with tickets 10 to 12, so the smoke test's "fake Generation" is the absence of any model or voice call, checked by asserting no request leaves the test host. Tests: `src/play/play.test.ts` (phases and Assistance States through the reducer), `src/play/visuals.test.ts` (worked examples per Skill and structure and stage), `src/play/path.test.ts`, `src/profile/profile.test.ts` (round trip with a Session in progress; corrupt data starts fresh), `src/ollie/poses.test.ts`, and `e2e/session.spec.ts` (creates the Profile by visiting, plays the Diagnostic Session with a first-try, a Hint-assisted, and a Revealed Problem, checks the recorded Assistance States, reaches the celebration, reloads and gets the six-Problem Baseline Session next; a second test reloads mid-Session and resumes the same Problem), run on desktop Chrome and the iPad landscape profile. Verified with `pnpm typecheck`, `pnpm lint`, `pnpm test` (241 tests), `pnpm test:e2e` (10), `pnpm licenses:check`. No new dependencies.

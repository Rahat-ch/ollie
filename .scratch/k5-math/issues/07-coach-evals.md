# 07: Coach evals and the convergence chart

**What to build:** The eval command now runs every Simulated Learner under both the Coach and the Baseline and reports: Hypothesis hit rate against planted weaknesses, Sessions to detection, false positives, Evidence Integrity (every cited ID exists and its Assistance State is consistent with the claim), and convergence versus Baseline, with held-out profiles scored separately. The chart shows Coach versus Baseline. This is the day-four checkpoint.

**Blocked by:** 06 Coach in the Loop

**Status:** resolved

- [x] False positives are Hypotheses marked supported that name a weakness the profile does not have; the rate is reported
- [x] Evidence Integrity is computed deterministically for every Hypothesis in every run and reported as a rate

## Comments

**2026-09-11, implementation.** The Eval Run now plays every Simulated Learner under both planners. `runLearner(learner, planner, sessions)` in `src/evals/run.ts` plays the Diagnostic Session and then one Session per Plan the planner returns, keeping the whole trace (each Session's result and the `CoachStep` after it); `baselinePlanner` is the fixed rule with empty Notes and `coachPlanner(generation)` is the Coach step from ticket 06 with its retry and Baseline fallback. Both run on the Learner's own seed, so their Diagnostic Sessions are byte-identical and every later difference is the planner's. `runEvals({ sessions, generation, generationName })` in `src/evals/evals.ts` runs the six Learners under the Baseline and under the Coach (the Coach runs concurrently across Learners, sequential within one) and returns convergence for both planners (`scoreConvergence` over a run, `convergenceReport` per planner, unchanged numbers) and the Hypothesis scores for the Coach run, each with the tuning and held-out splits scored separately. `scoreHypotheses(run)` in `src/evals/hypotheses.ts` is deterministic: a planted weakness is detected in the first Session after which a supported Hypothesis names it, where naming means the claim says the pattern in its own words (`namesWeakness`: "crosses ten", "bridges 10", "over ten", "regroup" for crossing ten; "missing addend", "missing part", "change unknown", "how many more" for change unknown) and never just the Skill, since every make-a-ten Problem crosses ten and the unknown-addend Skill has a plain subtraction structure the weakness is not planted on; a false positive is a supported Hypothesis naming a weakness the Learner does not have, counted once per Hypothesis id over the run, with the rate over distinct Hypotheses ever supported; Evidence Integrity (`checkEvidence`) checks every citation in every Session's Notes against the Log so far: the ID must exist, and its Assistance State must agree with the claim's polarity read from its words (`claimPolarity`: a difficulty claim, "misses", "struggles", "needs a Hint", cites Problems that were not first-try correct; a strength claim, "solid", "reliable", cites ones that were; a refuted Hypothesis or a claim with no polarity, a response-time pattern say, is checked for the ID only, since it legitimately cites either state); and `sources` tallies how many Plans came from the Coach, a retry, or the Baseline fallback. The report (`EvalReport`) is `generatedAt`, `sessions`, `targetAccuracyBand`, `coach.generation` (`fake` or the model id), `convergence.baseline` and `convergence.coach`, and `hypotheses` with per-Learner scores, the final Notes for audit, and the two splits. The chart draws two lines per facet, Coach in categorical slot 1 and Baseline in slot 2 of the dataviz reference palette (validated together on the paper surface: CVD ΔE 24.7, normal-vision 33.6, contrast above 3:1), with a legend, end labels, and the planted weakness's detection Session in the facet subtitle; its subtitle names the Generation that ran the Coach. `pnpm eval` runs the Anthropic adapter on Opus 5 by default, as the spec says real adapters run only under the eval command, printing a line per Session as each Learner's Coach run advances; `--fake` runs the Generation fake with no network and says on the console that its Coach columns show the seams and not the Coach's judgement. The console prints the tuning Learners and then the held-out Learners as separate sections, each with Sessions to Mastery per Skill Coach / Baseline, the Hypothesis table, and the split summary. `chooseGeneration` in `src/cli/generation.ts` is shared by `pnpm coach --real` and `pnpm eval`. Verified with `pnpm typecheck`, `pnpm lint`, `pnpm test` (210 tests), `pnpm eval --fake` (19 ms for 240 Sessions), `pnpm eval:chart`, `pnpm coach`, and the chart rendered and looked at.

Readings to confirm. The committed report and chart are from `pnpm eval --fake`, because there is still no `ANTHROPIC_API_KEY` on this machine: under the fake the Coach column beats the Baseline slightly on Skills Mastered (tuning mean 5.00 against 4.75; the Weak Learner Masters unknown addend in Session 19 where the Baseline never does) because the fake plans eight Problems per Session instead of six, and it never names a pattern, so detection is 0 of 2, false positives 0, and Evidence Integrity 100% over 2,297 citations. The day-four checkpoint as the spec means it, the real Coach against the Baseline, is one `pnpm eval` with a key away; the report and chart will then replace these. Detection is read from the claim's words with a fixed vocabulary per weakness, which is deterministic but can miss a phrasing (the final Notes are in the report so a miss can be audited), and the vocabulary was written knowing both weaknesses, including the held-out one; it is the scoring rule, not the prompt, and the prompt was not touched. Evidence Integrity reads a claim's polarity from its words too, and a difficulty claim that cites a first-try correct Problem as contrast counts as inconsistent, which is a choice: evidence should be what shows the pattern. Every Session's Notes are checked, so a Hypothesis kept unchanged for ten Sessions is counted ten times. Vocabulary gaps for domain modelling: "planner" (the Baseline rule or the Coach step), "detection", "false positive", and "claim polarity" are used in code and docs but are not in the glossary.
